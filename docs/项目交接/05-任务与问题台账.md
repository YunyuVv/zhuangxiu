## Bug 与代码隐患

本次没有运行真实业务场景。以下区分静态确认与待复现，不表示已在线上发生；修复前先用独立测试环境验证预期行为。

### B-001 · 自定义阶段未进入跨项目的分阶段统计

- 优先级/状态：P1，已定位（静态代码），运行待复现。
- 代码依据：`OverviewService.allOverview` 按 `Constants.STANDARD_PHASES` 逐一匹配阶段名；自定义名称/改名后的阶段被该列表跳过。总完成度仍按全部阶段计算，不能笼统写成“整个总览错误”。
- 建议复现：新建项目，增加“换窗”并完成；查看用户总览的分阶段进度是否包含该阶段。
- 验收：先确定跨项目自定义阶段应按名称聚合还是按项目展示，再修复；预算、花销和原标准阶段统计不回退。

### B-002 · 删除项目/阶段未处理附件

- 优先级/状态：P0，待复现（已有明确静态风险）。
- 代码依据：V1 中 `attachments.project_id` 外键引用 projects；`ProjectService.delete` 只删除花销、子项和阶段，再删项目，未删除附件。`PhaseService.delete` 同样未清理阶段/花销的多态附件引用。
- 建议复现：项目上传阶段照片后删除项目，观察外键错误与事务回滚；另测删除阶段后附件记录是否残留。
- 验收：按明确的保留/清理策略处理关联记录；有附件和无附件删除均正确，跨用户不能删除；图床远端删除是否支持需另行确认。

### B-003 · 花销阶段归属缺少同项目校验

- 优先级/状态：P0，待复现（静态发现）。
- 代码依据：`ExpenseService.create/update` 校验花销所属项目的 userId，却直接接受请求 phaseId；未见其阶段必须属于该项目的校验。外键仅保证阶段存在，不能保证同项目。
- 建议复现：账号 A 建项目/阶段，账号 B 创建自己的花销并传 A 的 phaseId；另测同一用户两个项目交叉关联与不存在阶段。
- 验收：非法关联在保存前被拒绝，原记录不改变；合法关联仍可保存，并验证统计和阶段删除影响。

### B-004 · 容器中的指南 SSR 后端地址未打通

- 优先级/状态：P1，待复现（配置链路待验证）。
- 代码依据：`guide.server.ts` 默认 `http://localhost:9096`；`next.config.mjs` 通过 env 暴露同名构建配置；前端 Dockerfile 构建时未设置后端地址，Compose web 环境也未提供 BACKEND_URL。容器的 localhost 指向 web 本身，Nginx 的浏览器代理不能解决 SSR 直连。
- 建议复现：按全栈 Compose 在隔离环境启动，对比 `/api/guides` 与 `/guide`；检查 Next 服务端请求目标和错误日志。
- 验收：在真实生产构建产物中，SSR 使用可达的后端服务地址；验证构建时和运行时配置语义，不能仅加运行时变量后假设已生效。

### B-005 · 图床 Key 接口的鉴权配置与实际调用链不一致

- 优先级/状态：P2，待核查（鉴权职责一致性，未发现匿名泄露的证据）。
- 代码依据：`SecurityConfig` 对 `/api/attachment/upload-key` 使用 permitAll，但 Controller 调用 `SecurityUtil.getCurrentUserId()`，后者在匿名身份下抛出 UNAUTHORIZED；因此不能仅凭 permitAll 断言匿名可获得 Key。Service 的 userId 参数未使用，鉴权目前依赖上层调用链。
- 建议验证：无 Authorization、过期 token、正常登录分别请求上传配置，核对 HTTP/业务状态与返回字段；不要将 Key 粘贴进文档、截图或测试日志。
- 验收：明确统一的鉴权职责；匿名/过期 token 不返回上传配置，正常登录可用，前端缓存行为不回退。若现有响应满足约定，可记录为维护性调整或暂不处理。

### B-006 · 删除阶段后记账列表可能仍显示旧数据

- 优先级/状态：P1，待复现。
- 代码依据：项目详情的 TimelineTab `onSaved` 只触发 loadPhases、loadOverview；阶段删除也会删除花销，但 expenses state 未同步重新加载。
- 建议复现：某阶段新增花销→删除该阶段→切换记账 Tab，对比页面列表、概览与后端数据。
- 验收：删除阶段后当前页花销列表和概览一致，刷新前后无差异；普通阶段改名/排序不引入额外错误。

### B-007 · Nginx 主配置原样包含 shell 默认值表达式

- 优先级/状态：P1，已修复待运行回归；默认 server_name 改为 _，另增 api.example.com 入口。
- T-011 后续：已改用官方镜像模板注入 FRONTEND_DOMAIN/BACKEND_DOMAIN，替换完成的主配置由启动脚本生成，Compose/本机 envsubst 验证通过，Nginx 容器运行仍待回归。
- 依据：`docker/nginx/nginx.conf` 的 server_name 使用 `${NGINX_SERVER_NAME:-localhost}`；Compose 原样挂载配置，未通过模板处理。不能期望 Nginx 自动执行 shell 替换。
- 验收：改为有效 server_name 或接入明确模板流程，nginx -t 及容器启动通过，域名/IP 的页面和 /api 路由正确。

### B-008 · JVM 镜像的 package 与 Native execution 绑定冲突风险

- 优先级/状态：P1，已修复，本地 JAR 验证通过，Linux 镜像待回归。
- 依据：pom 在主 build/plugins 中将 native:compile 绑定 package；JVM Dockerfile 在普通 Temurin Maven 镜像中执行 clean package，可能要求不存在的 Native 工具链。
- 实际复现与修复：补齐缺类后，旧 pom 的普通 package 仍执行 Native 插件并失败；现已移入 native profile，干净 Git 快照 clean package 成功，AOT 处理通过。
- 验收：普通 package 仅构建 JAR，native profile 构建原生程序；两条选定架构的 CI 路径均验证，不能只以 compile 通过代替。

### B-009 · Compose 后端未映射图床 Key

- 优先级/状态：P1，已定位（静态配置），图片功能运行待验证。
- 依据：公共配置从 APP_IMGBB_API_KEY 读取，但两份 Compose 后端 environment 均未传入；仅在 .env 中填写不会自动传入容器。
- 验收：需要图片的部署环境显式映射该变量，登录后真实上传及 URL 入库通过，验证中不输出 Key。

### B-010 · GitHub 后端构建缺少未跟踪源码

- 优先级/状态：P0，已修复待远端回归；关联 T-009。
- 证据：北京时间 2026-11-09 20:54 的 [JVM run](https://github.com/YunyuVv/zhuangxiu/actions/runs/42620919115) 与 [Native run](https://github.com/YunyuVv/zhuangxiu/actions/runs/42620918992) 都在 maven-compiler-plugin 报 cannot find symbol；SHA 为 145b2718dce152f587515c60a93fb2db8b6d0eae。
- 根因：PhaseCreateRequest、PhaseTask、PhaseTaskRepository 在本机但未被 Git 跟踪；引用它们的代码已提交。CI checkout 缺少类型，本机完整工作区编译掩盖问题。
- 修复：仅将三个必需文件纳入 Git 暂存，同时修复 B-008；不将其余未跟踪功能一并暂存。
- 后续 T-010：用户明确要求全部提交，剩余源码已一并纳入本地提交，完整快照 JAR/AOT 与前端构建通过；远端回归仍待推送。
- 验证：HEAD 导出的隔离源码快照复现同样缺类，补三文件和新 pom 后 clean package/AOT 通过，JAR 包含所需类型；新提交的 Linux amd64/arm64 CI 仍待触发。

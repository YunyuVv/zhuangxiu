# 代码与运行地图

核查日期：2026-11-09。以下路径以仓库根目录为基准；实现变动时同步维护对应条目。

## 功能定位

Java 包根目录为 `server/src/main/java/com/biliww/zhuangxiu/`。当前按 controller/service/repository/domain/dto 分层，并非旧设计文档中的 module 目录结构。

| 功能 | 页面/前端入口 | 后端调用链与数据 |
| --- | --- | --- |
| 登录注册 | `web/src/app/login/page.tsx`、`register/page.tsx`；`lib/auth.ts`、`lib/api.ts` | `AuthController → AuthService`；`security/JwtProvider`、`JwtAuthenticationFilter`；users |
| 首页总览 | `web/src/app/page.tsx` | `GET /api/projects/overview → OverviewController → OverviewService.allOverview` |
| 项目列表/新建 | `web/src/app/projects/page.tsx`、`projects/new/page.tsx` | `ProjectController → ProjectService → ProjectRepository`；projects、phases |
| 时间线 | `web/src/app/projects/[id]/page.tsx` 中 TimelineTab、PhaseCard | `PhaseController → PhaseService`；phases、expenses、phase_tasks |
| 阶段检查项 | 同上 PhaseCard | `PhaseTaskController → PhaseTaskService`；phase_tasks |
| 花销 | 同上 ExpenseTab；`web/src/lib/types.ts` | `ExpenseController → ExpenseService → ExpenseRepository`；expenses |
| 单项目概览 | 同上 OverviewTab | `GET /api/projects/{id}/overview → OverviewService.get` |
| 图片 | `web/src/components/UploadImage.tsx` | `AttachmentController → AttachmentService`；attachments；浏览器直传 imgbb |
| 装修指南 | `web/src/app/guide/page.tsx`、`guide/[stageKey]/page.tsx`、`lib/guide.server.ts` | `GuideController → GuideService → GuideRepository/GuideDetailRepository`；guides、guide_details |
| 我的/退出 | `web/src/app/me/page.tsx`、`lib/auth.ts` | 本地清除 token 与用户信息，无后端 logout |
| 错误/鉴权 | `web/src/lib/api.ts` | `config/SecurityConfig`、`common/GlobalExceptionHandler`、`ErrorCode`、`ApiResult` |

## 当前接口速查

| 路径 | 方法/用途 |
| --- | --- |
| `/api/auth/register`、`/api/auth/login` | POST，注册/登录 |
| `/api/projects` | GET 列表、POST 新建 |
| `/api/projects/{id}` | GET、PUT、DELETE |
| `/api/projects/{projectId}/phases` | GET、POST |
| `/api/phases/{phaseId}` | PUT、DELETE |
| `/api/phases/{phaseId}/tasks` | GET、POST |
| `/api/tasks/{id}` | PUT、DELETE |
| `/api/projects/{projectId}/expenses` | GET、POST；GET 支持 phaseId、page、size |
| `/api/expenses/{id}` | GET、PUT、DELETE |
| `/api/projects/{id}/overview` | GET，单项目概览 |
| `/api/projects/overview` | GET，当前用户全部项目总览 |
| `/api/attachment/upload-key` | GET，图床配置；当前 Security 放行，见 B-005 |
| `/api/attachment` | POST，保存附件 URL |
| `/api/guides`、`/api/guides/{stageKey}` | GET，公开列表与详情 |

业务返回由 `ApiResult` 包装（code/message/data）；分页为 total/page/size/list，page 从 0 开始。鉴权错误可能由 Security 直接响应，排障时同时看 HTTP 状态和响应体，不假设所有错误都已统一包装。

## 迁移地图

目录：`server/src/main/resources/db/migration/`。

| 迁移 | 内容 |
| --- | --- |
| V1__init.sql | users、projects、phases、expenses、attachments |
| V2__guide.sql | guides、guide_details 与标准阶段种子内容 |
| V3__phase_custom.sql | expenses.name（可空，兼容存量）与 phase_tasks 表/索引 |

V3 的新花销名称由创建 DTO `@NotBlank` 校验，数据库列本身可空；前端兼容历史记录无名称。迁移文件存在不代表已执行。启动会触发 Flyway，应先明确目标数据库；查询目标库 `flyway_schema_history` 才能确认迁移结果，记录时不要附带连接密码。已执行的迁移不要重写，需要修正时新增下一版本。

## 环境与检查命令

本次本机观察：Node 24.11.0、pnpm 10.20.0、Maven 3.8.8、OpenJDK 25.0.1。`.java-version=25`，但本次 Maven 实际使用普通 OpenJDK，**没有验证 GraalVM 工具链**。Docker 前端为 Node 22 / pnpm 9，不要把本机版本与容器版本混为一谈。

```bash
# 仓库根目录，接手前先核对已有改动
git branch --show-current
git rev-parse HEAD
git status --short
git diff --stat
git diff --cached --stat

# 前端：首次依赖安装，随后检查和运行
cd web
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit --incremental false
pnpm dev
# 开发端口 9095；当前 /api rewrite 目标是 localhost:9096

# 后端：在另一终端，从仓库根目录进入
cd server
java -version
mvn --version
mvn -o -DskipTests compile
# 仅在测试数据环境配置核对后启动；会运行 Flyway
mvn spring-boot:run
```

离线编译依赖本机 Maven 缓存；新机器缓存不全时去掉 `-o` 联网获取依赖。上述独立检查的本次执行结果见当前状态；安装、启动与生产构建不属于本次已执行验证。

- 默认 profile 是 `test`，本机私有配置 `application-test.yml` 存在且被忽略，不随普通 clone 传递。新环境参考 `application-test.yml.example` 配置独立测试库；不要假设 clone 后可直接运行。
- 后端端口 9096，Swagger 路径 `/swagger-ui.html`；生产配置为 `application-prod-docker.yml`，按 DB_*、REDIS_*、APP_JWT_SECRET、APP_IMGBB_API_KEY 等变量配置，具体以文件为准。
- 指南 SSR 使用 `web/src/lib/guide.server.ts` 与 `next.config.mjs` 中的 BACKEND_URL；浏览器 `/api` 代理和 SSR 直连是两条不同链路。
- `pnpm build` 是 Next 生产构建检查；`mvn -Pnative -DskipTests native:compile` 需要 GraalVM。当前 pom 还将 Native compile 绑定到 package，执行 package 前核对 profile 与工具链，勿把它等同于轻量 compile。

## 部署文件与排障顺序

- 全栈编排：`docker/docker-compose.yml`；仅后端：`docker/docker-compose-server.yml`；仓库根目录没有 Compose 文件。
- 前端/JVM/Native 镜像定义分别在 `docker/frontend/Dockerfile`、`docker/backend/Dockerfile.jvm`、`Dockerfile.native`。
- `.github/workflows/` 下三个工作流负责构建并推送 GHCR；这些文件不能证明服务器已经更新。记录实际 workflow run、镜像 digest/标签、目标环境和验收结果才能称为发布。
- Nginx 配置在 `docker/nginx/nginx.conf`；部署说明见 [线上环境](../线上环境/1-部署架构与方式介绍.md) 与 [Linux 部署指南](../线上环境/2-Linux上Docker部署指南.md)。配置中模板替换等疑点应结合容器实际检查，不将旧指南视为验证结果。

| 症状 | 优先检查 |
| --- | --- |
| 前端 /api 不通 | 浏览器 Network → Next rewrite 或 Nginx → 后端监听/日志，核对 9095/9096 与容器 3000 |
| 登录后跳回登录 | HTTP 401/403、JWT 过期、Authorization、api.ts 拦截；403 当前也会清 token |
| 表/列不存在 | 当前 profile、目标数据库、Flyway 启动日志与 history，特别是 V2/V3 |
| 删除失败或残留 | ProjectService/PhaseService 删除顺序、attachments 外键/多态关联、事务回滚 |
| 指南报加载失败 | 单独检查 Next 服务端到后端的 BACKEND_URL；浏览器 API 正常不能证明 SSR 链路正常 |
| 自定义阶段不出现在总览 | OverviewService.allOverview 的标准阶段遍历，而非先修改前端 |
| 图片刷新后不见 | UploadImage 的本地 preview 与附件持久化是两件事；核对读接口/展示链路是否实现 |

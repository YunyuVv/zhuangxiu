# 开发环境启动步骤

本文档说明如何在本地把「装修记录」项目的前后端跑起来，供开发联调使用。

## 一、环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| Java | **JDK 25（graalvm，jenv 管理）** | 本机用 `jenv` 管理，进入 `server/` 目录自动切到 `graalvm64-25`（自带 Native Image）。Spring Boot 4 要求 Java 17+。 |
| Maven | 3.8+ | 后端构建与运行。 |
| Node.js | 18+（本机 22） | 前端运行环境。 |
| pnpm | 10+ | 前端包管理（统一用 pnpm，不用 npm/yarn）。 |
| 数据库 | 云端 PostgreSQL（Neon） + Redis（Upstash） | 连接串已写死在 `server/src/main/resources/application-test.yml`，无需本地 Docker。 |

> 包名：`com.biliww.zhuangxiu`
> 后端端口：**9096**；前端端口：**9095**（开发服务器，已在 `web/package.json` 的 `dev` 脚本固定 `-p 9095`）

---

## 二、后端启动（Spring Boot 4）

### 介绍
- 技术栈：Spring Boot 4 + Maven，Java 25（graalvm），全量兼容 GraalVM Native Image。
- 数据库：PostgreSQL（Neon 云库）+ Redis（Upstash 云库），连接信息写在 `application-test.yml`。
- 接口文档：Springdoc OpenAPI 自动生成，启动后访问 Swagger UI。
- 多环境：主 `application.yml` 默认 `spring.profiles.active: test`；生产用 `application-prod-docker.yml`（占位，环境变量注入）。

### 启动命令

```bash
cd /Users/wangpenglong/projects/full-stack-project/zhuangxiu/server

# jenv 进入目录会自动切换到 graalvm64-25（无需手动 export）
# 确认版本：
jenv version        # 应显示 graalvm64-25

# 启动（默认激活 test 环境，直连云端 PG + Redis）
mvn spring-boot:run
```

### 验证
- 应用日志出现 `Started ZhuangxiuApplication` 即启动成功。
- 接口文档（Swagger UI）：`http://localhost:9096/swagger-ui.html`
- 启动后 Flyway 会在 Neon 库自动建表（users / projects / phases / expenses / attachments）。

### 其他
- 生产环境启动：`mvn spring-boot:run -Dspring-boot.run.profiles=prod-docker`
- 注意：`application-test.yml` 含真实数据库密码，勿提交到公开仓库（纳入 git 时请加 `.gitignore`）。

## 三、前端启动（Next.js + pnpm）

### 介绍
- 技术栈：Next.js（App Router + TypeScript），pnpm 管理依赖，移动优先布局。
- 接口调用：通过 `/api` 路径代理到后端。开发期代理目标已配置为 `http://localhost:9096/api/:path*`（见 `web/next.config.mjs`），前端代码只需请求相对路径 `/api/...`，无需关心后端地址。
- 核心功能页：登录/注册、项目列表、新建项目、项目详情（时间线 / 记账 / 概览 三个 Tab）、图片上传组件（前端 Canvas 压缩最长边 1920@0.8 后直传 imgbb）。

### 启动命令

```bash
cd /Users/wangpenglong/projects/full-stack-project/zhuangxiu/web

# 1. 安装依赖（首次需要，之后可跳过）
pnpm install

# 2. 启动开发服务器
pnpm dev
```

### 验证
- 前端页面：`http://localhost:9095`
- 接口经 `/api` 代理到后端 `http://localhost:9096`（需后端已启动）。

## 四、完整联调流程（推荐顺序）

1. 后端先起：见「二」，确认 Swagger 可访问、数据库已建表。
2. 前端后起：见「三」，打开 `http://localhost:9095`。
3. 走通主路径：
   - 注册一个账号 → 登录
   - 新建项目（自动初始化 8 个标准阶段）
   - 在时间线标记阶段状态、上传阶段照片
   - 在记账页记一笔花销（选分类、归属阶段）
   - 在概览页看总预算 / 已花 / 各阶段预算 vs 实际 / 超支预警

## 五、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 编译报 `找不到符号 getXxx()/setXxx()` | Lombok 注解处理器未生效。`pom.xml` 的 `maven-compiler-plugin` 已配置 `annotationProcessorPaths` 包含 Lombok，确保依赖已重新下载。 |
| 后端监听随机端口（非 9096） | `server.port` 需在激活的 profile 中生效；`application-test.yml` 已显式写 `server.port: 9096`。确认启动日志中 `Tomcat started on port 9096`。 |
| 前端请求 502 / 连不上后端 | 后端未启动，或 `localhost:9096` 被本地代理拦截。用 `curl --noproxy '*' http://localhost:9096/swagger-ui.html` 直连验证；前端 `pnpm dev` 时确认后端在线。 |
| `pnpm install` 报错 | 检查 Node 版本（需 18+）、pnpm 是否安装（`pnpm -v`）。把报错贴给开发同学。 |
| 数据库连不上 | 检查 `application-test.yml` 的 Neon/Upstash 连接串；Upstash 为 Serverless Redis，空闲连接可能短暂不可用，重试即可。 |
| **启动成功但注册报 `relation "users" does not exist`** | **Spring Boot 4 模块化：Flyway 自动配置已拆到独立 starter。仅靠 `flyway-core` 不会触发任何迁移（日志也无报错，静默不建表）。修复：依赖必须引 `spring-boot-starter-flyway`（已写入 `pom.xml`），而非 `flyway-core`。加上后重启，Flyway 自动建表。详见 `技术设计文档.md` 说明。** |

## 六、目录速览

```
zhuangxiu/
├── server/                 # 后端 Spring Boot 4（Maven，包名 com.biliww.zhuangxiu）
│   ├── pom.xml
│   └── src/main/resources/
│       ├── application.yml          # 公共配置，默认激活 test
│       ├── application-test.yml      # 云端 PG + Redis（连接串写死）
│       └── application-prod-docker.yml  # 生产占位（环境变量注入）
├── web/                    # 前端 Next.js（pnpm）
│   ├── package.json
│   └── src/app/            # 登录/注册/项目/详情等页面
├── miniprogram/            # 微信小程序（占位，暂不开发）
├── docker-compose.yml      # 本地 PG + Redis（可选，当前用云库）
└── docs/                   # 需求/设计/评审/启动文档
```
